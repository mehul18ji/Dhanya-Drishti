## 0. Executive summary — what this project actually is

DhanyaDrishti is **not** a deep-learning app and **not** a farmer product. It is a
**mentor/evaluator-facing academic web dashboard** that demonstrates a *complete classical
computer-vision + classical machine-learning pipeline* end to end.

A user uploads **one photograph of a diseased rice leaf**. The system:

1. Validates and safely decodes the file (EXIF-corrected, no stretching).
2. Runs deterministic classical CV: HSV/Lab colour analysis, K-Means clustering,
   morphological cleanup, connected components.
3. Segments the **leaf**, then segments the **lesion regions inside that leaf**.
4. Extracts a **versioned numeric feature vector** (colour, GLCM texture, shape,
   lesion-area, spatial distribution).
5. Feeds it to the **best of SVM / Random Forest / KNN**, chosen by macro-F1 on a
   stratified protocol (96 train / 24 held-out test, 5-fold CV).
6. Returns **disease label + confidence + lesion-area % + experimental severity
   (Mild/Moderate/Severe) + warnings**, or an honest `uncertain` / `rejected` state.
7. Keeps **temporary, in-memory-runtime** prediction history (SQLite + temp files,
   wiped on restart).

The intellectual value being graded is **methodological honesty**:
- only 3 labels from a 120-image dataset; no healthy class;
- no augmentation-inflated scores;
- no "accuracy = real-world reliability" claims;
- severity is explicitly an experimental lesion-area estimate;
- features, splits, seeds and thresholds are versioned and reproducible.

**What it stands for when finished:** a small, honest, fully documented, reproducible
reference implementation of the professor's required workflow — a working local app that
can also be deployed to Vercel + Render, with a model card that states its own limits.

## 2. Dataset audit — measured facts that shape the design

Class counts verified: **40 / 40 / 40 = 120**.

| Class (folder) | Images | Resolution range | Notes |
|---|---:|---|---|
| Bacterial leaf blight | 40 | every image exactly **3081×897**, aspect 3.43 | Uniform scan/crop batch → beware of "resolution as a shortcut feature" |
| Brown spot | 40 | **286×88 → 3081×900**, aspect 1.33–5.30 | Mix of tiny close-ups and full leaf strips |
| Leaf smut | 40 | **250×71 → 4160×2340**, aspect 1.25–5.03 | Includes one 2.2 MB / 4160×2340 outlier |

All files are RGB JPEG/JPG. No exact duplicate files (MD5) found.

### Critical findings that change implementation decisions

1. **Some images have no background at all.** 13 images are >70% leaf-green pixels
   (median green fraction is ~37.5%). Example: `Leaf smut/DSC_0508.jpg` and
   `DSC_0515.jpg` are pure leaf close-ups.
   → Leaf segmentation **must** have a documented fallback: *"if green/leaf-like
   fraction ≥ ~65% of the frame, treat the whole frame as the leaf mask"*. Without this,
   these images return `NO_CLEAR_LEAF_FOUND` and the model loses real training/demo data.

2. **Nine images are tiny** (short side < 128 px; smallest 301×71).
   → A naive "image too small" gate (e.g. min 256 px) would reject 25/120 dataset images
   and 9/120 at a 128 px gate. Set **hard reject ≈ 64 px short side**, **soft warning ≈ 224 px**,
   and document the boundary cases.

3. **Leaf is a long thin strip on a bright paper background** in most images.
   → Contour scoring must not prefer "most square" candidates; prefer *largest area*
   with a mild centrality bonus, and compute aspect-ratio features up to ~5:1.
   Closed contour + convex-hull fill is needed so the lesion mask is not clipped.

4. **Lesions are brown/tan/grey relative to green tissue.** On close-ups, brown spot
   and smut lesions are small (a few dozen pixels).
   → Lesion segmentation needs **relative** thresholds (compare against the leaf's own
   green statistics) rather than only absolute HSV ranges, plus a *minimum lesion size*
   that can scale with image resolution (area-relative, not fixed pixels).

5. **Near-duplicate detection cannot rely on a coarse 8×8 average hash.** It flagged
   298 "pairs" across classes, which is clearly false positives on visually similar
   leaf-on-white-background scans.
   → Use a stronger combination: dHash 16×16 + HSV histogram distance + SSIM on a
   normalized 256 px canvas, and report candidates for *manual* review. If a cross-class
   near-duplicate pair is confirmed, exclude per PRD §10.

6. **Resolution is a leakage risk.** All BLB images share 3081×897. Never include raw
   resolution in the feature vector; normalize all geometry to the processing canvas
   (e.g. 512 px long side / letterboxed) and use scale-invariant ratios.

### Split plan (from PRD §10, made concrete)

- Held-out test: **24 images = 8 per class**, fixed and saved to `data/splits/test.json`.
- Remaining **96 = 32 per class**, stratified 5-fold CV in `data/splits/cv_folds.json`.
- One global seed (e.g. `SEED=42`) used by: split generation, K-Means, RF, and any
  resampling. Stored in the split manifest and config.
- Split selection happens **after** near-duplicate review.
- No augmentation for baseline scores; if augmentation is used at all, it is a separate
  clearly-labelled experiment, never in the headline metrics.

## 3. Target architecture (as it will be built)

```text
Browser (React/Vite/TS/Tailwind, port 5173)
   │  multipart POST /api/v1/predict
   ▼
FastAPI (port 8000)
   routes_predict → upload_validation → preprocessing → leaf_segmentation
                  → lesion_segmentation → feature_extraction
                  → inference (model loaded once at startup)
                  → severity → history_service (SQLite + temp artifacts)
   ▼
JSON response (predicted | uncertain | rejected)
```

Offline (never at request time):

```text
scripts/audit_dataset.py → data/splits/*.json
notebooks/01..05         → parameter discovery (throwaway)
scripts/train_model.py    → artifacts/production/{model.joblib, preprocessing.joblib,
                            feature_schema.json, segmentation_config.json,
                            model_manifest.json, evaluation_report.json}
```

Non-negotiable invariants:

- **Single feature extractor module** used by both `training.py` and `inference.py`.
- `feature_schema.json` holds the ordered feature-name list + `feature_set_version`.
  The API refuses to serve if the loaded schema version ≠ manifest version.
- **All thresholds live in YAML** (`configs/segmentation.yaml`, `severity.yaml`,
  `quality_thresholds.yaml`) and are hashed into the manifest.
- No model training inside a request handler.
- No image persisted beyond the configured expiry / runtime.

### Phase 2 — Classical CV pipeline (the heart of the grade)

**Goal:** deterministic, config-driven, visually verifiable leaf + lesion segmentation.

**Tasks**
1. `vision/preprocessing.py`:
   - EXIF orientation (`PIL.ImageOps.exif_transpose` or OpenCV EXIF flag),
   - `resize_preserving_aspect()` + `letterbox_pad(canvas=512)` returning the scale/pad
     transform (needed to map masks back to original preview),
   - denoise (bilateral or fastNlMeans, kernel from config).
2. `vision/quality.py`: brightness (mean V), contrast (std V), over-exposure (% pixels V>245),
   blur (variance of Laplacian), min dimensions, decode failure, leaf-fraction checks.
   Emit **warnings** vs **hard rejects** as separate lists.
3. `vision/leaf_segmentation.py`:
   - HSV + Lab candidate masks for green/yellow/brown,
   - K-Means (k=3–4, `random_state=SEED`) on downsampled pixels, merge clusters whose
     centroids are leaf-like,
   - morphology open/close, small-region removal, connected components,
   - candidate scoring: area, fill ratio vs convex hull, centrality, border-touch penalty,
   - **background-free fallback** (leaf fraction ≥ 0.65 → full-frame mask),
   - multi-leaf detection → pick primary + warning string from PRD §7,
   - **failure** → `NO_CLEAR_LEAF_FOUND` rejection.
4. `vision/lesion_segmentation.py`:
   - restrict to leaf mask, convert to HSV/Lab,
   - lesion conditions **relative** to leaf statistics (hue distance from leaf median hue,
     LAB a*/b* deviation, value drop) + absolute guard rails from YAML,
   - K-Means separation of visually distinct clusters,
   - morphology to remove specks / fill pin-holes, min lesion area scaled by image area,
   - final lesion mask ∩ leaf mask.
5. Artifacts: original preview, leaf mask overlay, lesion mask overlay, side-by-side
   diagnostic PNG for review (`image_artifact_service.py`).
6. `notebooks/02_segmentation_experiments.ipynb`: tune on ~15 images (5/class across the
   size spectrum), then run all 120 and record pass/fail counts.
7. Everything probabilistic fixes a seed; every threshold goes to `configs/segmentation.yaml`
   with a `segmentation_config_version`.

**Deliverables:** preprocessing, quality, leaf segmentation, lesion segmentation modules,
config YAML, mask visualizations, `docs/SEGMENTATION_NOTES.md` (with before/after grids),
a shared pipeline orchestrator and a reproducible 120-image audit script.

**Definition of done**
- Portrait, landscape, square, 5:1 strip, and pure-close-up images all process **without
  distortion** (verify: aspect ratio of the leaf bbox is preserved to < 1%).
- ≥ 110/120 dataset images produce a plausible leaf mask; the rest are either rejected
  with a reason or produce the documented full-frame fallback.
- Multi-leaf synthetic test (two leaves pasted side by side) yields the warning + primary leaf.
- A non-leaf image (e.g. text photo) returns `rejected`, not a disease.
- Deterministic: two runs on the same file give identical masks.

**Risks (highest in the project)**
- Over-tuned HSV ranges that only work on this dataset's white background → document the
  limitation and keep ranges in YAML so they are adjustable.
- Lesion mask swallowing shadow/leaf edges → use leaf-mask erosion before scoring and a
  "distance from leaf border" exclusion band (config).
- Total segmentation failure on close-ups → the 0.65 full-frame fallback is mandatory.

**M1 — Configuration and reproducibility**

- Evidence: `tests/test_preprocessing.py`, `tests/test_quality.py`; the <1 % aspect-drift
  assertion across portrait/landscape/square/5:1.
- DoD: no distortion on any aspect ratio; over-exposure is judged inside the leaf mask only
  (decision E-19).

**M3 — Leaf segmentation**
- Purpose: find one plausible primary leaf, or refuse honestly.
- Deliverables: `app/vision/leaf_segmentation.py` — HSV green/yellow/brown candidates + Lab
  chroma, seeded K-Means merge, morphology and component cleanup, area/centrality/border

  warning (verbatim PRD §7 text), `NO_CLEAR_LEAF_FOUND` failure.
- Evidence: `tests/test_leaf_segmentation.py`; the leaf-mask column of the 120-image audit.
- DoD: synthetic single-leaf, close-up, two-leaf and non-leaf cases behave as documented, and
  two runs on the same image give identical masks.

**M4 — Lesion-region segmentation**
- Purpose: find lesions **relative to the leaf's own tissue**, never by absolute colour alone.
- Deliverables: `app/vision/lesion_segmentation.py` — leaf-relative HSV/Lab shifts (hue
  distance, a*/b* deviation, value drop), seeded K-Means cluster agreement, morphology,
  minimum component scaled by leaf area, border-exclusion band, final leaf-mask intersection,
  plausibility warning, and an explicit "no healthy reference" unreliable state.
- Evidence: `tests/test_lesion_segmentation.py`; the lesion column of the audit.
- DoD: the lesion mask never leaves the leaf; a fully brown/necrotic leaf is reported as
  unreliable (never as "0 % lesions"); identical runs give identical masks.

**M5 — Shared pipeline orchestration and diagnostic outputs**
- Purpose: one composition of the stages, used by the audit script now and the API in Phase 4.
- Deliverables: `app/vision/pipeline.py` (typed result carrying quality report, leaf/canvas/

- Evidence: `tests/test_vision_pipeline.py`, `tests/test_diagnostics.py`, and the panels the

- DoD: one call turns bytes or a path into masks + quality report + timings; the module persists

### Phase 3 — Feature extraction and SVM / Random Forest / KNN comparison

**Goal:** one documented feature schema, three trained models, one honest winner.

**Tasks**
1. `vision/feature_extraction.py` — single source of truth:
   - **Colour:** per-channel mean/std + selected histogram stats for RGB, HSV, Lab
     (skip channels that are constant/near-constant; keep the order fixed).
   - **Texture:** GLCM on the leaf-region greyscale (`scikit-image`): contrast,
     homogeneity, energy, correlation, dissimilarity (entropy only if stable).
   - **Shape:** leaf area (normalized by canvas), perimeter, aspect ratio, compactness,
     circularity, solidity.
   - **Lesion:** lesion count, lesion/leaf ratio, largest-lesion ratio, mean lesion size,
     lesion perimeter/area stats.
   - **Spatial:** centroid distance from leaf centroid, spread (std of lesion pixel
     coordinates normalized by leaf bbox), quadrant distribution, border-distance stats.
   - Output: `np.ndarray` float32 in the exact schema order + `feature_schema.json`
     (`version: "1.0.0"`, names, order, extractor version, config hashes).
2. `scripts/build_feature_matrix.py` → cached `data/processed/features_v1.csv` (+ `.npy`)
   for all 120 images, with per-image failures recorded (never silently filled).
3. `ml/training.py`:
   - Pipelines: `StandardScaler+SVM(RBF, probability=True)`, `RandomForest`,
     `StandardScaler+KNN`; small `GridSearchCV` **inside** each CV fold (no leakage).
   - Stratified 5-fold CV on the 96; report mean ± std for accuracy, balanced accuracy,
     macro P/R/F1.
   - Select by **macro F1**; then evaluate once on the 24 held-out images.
4. `ml/evaluation.py` → `evaluation_report.json` + confusion matrices + per-class table,
   auto-written as Markdown too.
   Include baseline sanity: majority-class and random baselines so the report is honest.
5. `ml/outlier_detection.py`: fit on training features — e.g. `IsolationForest` +
   Mahalanobis/`NearestNeighbors` distance; export thresholds for the `uncertain` gate.
6. `notebooks/04_model_comparison.ipynb`: the human-readable comparison narrative.
7. `scripts/export_artifacts.py` → `backend/app/artifacts/production/`:
   `model.joblib`, `preprocessing.joblib`, `feature_schema.json`,
   `segmentation_config.json`, `model_manifest.json` (model name, feature-set version,
   CV + test metrics, training timestamp, dataset version/checksum, segmentation config
   version, known failure cases), `evaluation_report.json`.
8. `notebooks/05_error_analysis.ipynb`: list every misclassified test image with its masks;
   this feeds `docs/MODEL_CARD.md` in P6.

**Deliverables:** feature extractor, feature matrix, trained+compared models, evaluation
report, production artifacts, model-comparison notebook.

**Definition of done**
- The three models are compared on the *same* frozen features and split; the winner is
  justified only by macro F1 (CV mean, then confirmed on held-out test).
- `feature_schema.json` order == the array order produced by the extractor for a fresh image
  (asserted by a unit test).
- A clean Python process can `joblib.load()` the artifacts and predict a hand-crafted
  feature row without importing training code — PRD §25 Phase 3 DoD.
- No augmentation; no scaling fitted outside folds; no resolution leakage.
- Report states explicitly that scores are optimistic/inflated by dataset size and
  visual similarity — not real-world accuracy.

**Risks**
- 96 training samples with ~60–120 features → overfitting. Mitigate: feature-count budget,
  variance/correlation pruning (`VarianceThreshold`, drop |r|>0.95 pairs), simple models,
  and reporting CV variance, not just the best number.
- Perfect/near-perfect accuracy is a red flag, not a success → investigate leakage before
  celebrating; document the investigation.

### Phase 4 — FastAPI inference service

**Goal:** a typed, tested API that never retrains and never leaks files.

**Tasks**
1. `core/config.py` (Pydantic Settings) reading env + YAML; `core/exceptions.py` mapping
   domain errors → HTTP codes; `core/logging.py` structured request logs with `prediction_id`.
2. `services/upload_validation.py`: extension allowlist (jpg/jpeg/png/webp), real-format
   sniffing via Pillow (`verify()`), size limit from env, dimension checks, EXIF handling.
3. `services/preprocessing_service.py` → orchestrates vision modules; returns a typed
   `PipelineResult` (leaf mask, lesion mask, features, quality flags, warnings, artifacts).
4. `services/inference_service.py`: load artifacts **once** at startup (lifespan);
   validate schema version; produce probabilities; apply the `uncertain` rules from PRD §11.
5. `vision/severity.py`: thresholds from `configs/severity.yaml` (<10 Mild, 10–<25 Moderate,
   ≥25 Severe), boundary-safe, always attaches the disclaimer string.
6. `db/` + `services/history_service.py`: SQLite in `RUNTIME_DIR`, table schema,
   expiry sweep, startup wipe, graceful-shutdown cleanup, `DELETE /api/v1/history`
   removing rows **and** artifact files.
7. `services/image_artifact_service.py`: serve `original`, `leaf-mask`, `lesion-mask`
   per prediction id; 404 on unknown/expired; no path traversal (ids must be validated UUIDs).
8. Routes: `health`, `model-info`, `predict`, `history` (GET/DELETE), artifact GETs.
   Response models exactly per PRD §15; add `warnings[]`, `reason_code`, `recommended_action`.
9. CORS for `http://localhost:5173` from env; request size/time limits; 413/415/422/500 mapping.
10. Tests (`backend/tests/`): valid upload, bad extension, corrupt bytes, oversize, model
    not loaded, predicted, uncertain, rejected, history get/delete/expiry, artifact 404,
    UUID validation, no-temp-file-left-behind.

**Deliverables:** full API with OpenAPI docs, temp storage + history, API test suite, `docs/API.md`.

**Definition of done**
- `POST /api/v1/predict` with a dataset image returns a schema-valid `predicted` response
  with artifacts that actually render.
- A healthy-leaf photo returns `uncertain` (never "healthy").
- A text screenshot returns `rejected` with `NO_CLEAR_LEAF_FOUND`.
- Restarting the backend clears history; `DELETE /api/v1/history` removes rows + files.
- Response time on CPU is acceptable (target < 3 s/image at 512 px) and measured in the log.
- Tests green: `pytest -q`.

## 6. Suggested starting configuration (calibrate in P2/P3, then freeze)

> Values are **starting points for calibration**, not validated constants. They must end up
> in YAML with a version string.

```yaml
# configs/segmentation.yaml
canvas_long_side: 512          # letterbox, never stretch
kmeans:
  seed: 42
  k_leaf: 4
  k_lesion: 3
  sample_max_pixels: 20000
leaf:
  hsv_ranges:                  # green / yellow-green / brown leaf tissue
    green:  {h: [25, 95],  s: [35, 255], v: [25, 255]}
    yellow: {h: [15, 35],  s: [40, 255], v: [40, 255]}
    brown:  {h: [5, 22],   s: [30, 255], v: [20, 200]}
  morph_open: 5
  morph_close: 7
  min_component_ratio: 0.01     # of image area
  full_frame_fallback_green_ratio: 0.65
  border_touch_penalty: 0.15
  multi_leaf_min_area_ratio: 0.15
lesion:
  border_exclusion_px: 6        # scaled to canvas
  min_lesion_area_ratio: 0.0005 # of leaf area (scaled, not fixed px)
  morph_open: 3
  morph_close: 5
  relative_hue_delta: 12        # degrees from leaf median hue
  lab_ab_delta: 8
```

```yaml
# configs/quality_thresholds.yaml
min_short_side_reject: 64
min_short_side_warn: 224
max_upload_mb: 10
brightness:
  warn_mean_v_low: 55
  warn_mean_v_high: 215
  overexposed_pixel_ratio: 0.08
blur:
  warn_laplacian_var: 60        # computed on the resized canvas
segmentation:
  leaf_area_min_ratio: 0.03
  lesion_mask_sanity_min_ratio: 0.0
```

```yaml
# configs/severity.yaml
mild_max: 10        # < 10 %
moderate_max: 25    # 10 – < 25 %
severe_min: 25      # >= 25 %
disclaimer: "Severity is an experimental estimate based on the visible lesion area in this image. It is not a validated agronomic severity grade."
```

Uncertainty gate (calibrated in P3, not hand-picked):

```text
uncertain  if  max_probability < calibrated_threshold      (e.g. tuned on CV out-of-fold probs)
        or  any soft quality warning is active
        or  feature vector flagged as outlier (IsolationForest / kNN distance)
        or  leaf-segmentation confidence score < threshold
        or  multiple leaf candidates are ambiguous
```

## 7. Cross-cutting engineering rules (do not violate)

1. **One extractor.** Training and inference call the same `feature_extraction` code path.
2. **Version everything.** `feature_set_version`, `segmentation_config_version`,
   `dataset_version` (checksum), `model_version` — all surfaced in `model_manifest.json`
   and `/model-info`.
3. **No silent fallbacks.** If a stage fails, return a typed reason code; never substitute
   zeros for features.
4. **No training in requests.** Startup load only.
5. **No permanent storage.** Temp dir + SQLite, wiped on start, expiry sweep, shutdown cleanup.
6. **No stretching, no blind centre crop.** Resize → crop-to-leaf-bbox-with-margin → resize
   preserving aspect → letterbox.
7. **Determinism.** Fixed seeds for splits, K-Means, RF; tests assert reproducibility.
8. **Honesty over scores.** Every report includes baselines, CV variance, dataset size, and
   a plain statement that this is not field-validated.
9. **Disclaimer parity.** The exact texts from PRD §3, §7, §11, §12 appear in both API and UI.
10. **Config over constants.** Any numeric threshold lives in YAML/env, not in a route handler.

## 9. Risk register

| # | Risk | Impact | Mitigation |
|---|---|---|---|
| R1 | Lesion segmentation unreliable on close-ups / shadows | Wrong lesion area → wrong severity | Leaf-border exclusion band, relative thresholds, visual review of all 120, fallback to "lesion estimate unreliable" warning |
| R2 | Tiny dataset → unstable CV, misleadingly high accuracy | Academic credibility | Report CV mean ± std, per-class F1, baselines, confusion matrix, explicit caveat; no augmentation in headline numbers |
| R3 | Resolution leakage (BLB all 3081×897) | Fake accuracy | Exclude raw dimensions from features; use normalized ratios only |
| R4 | Near-duplicate leakage across train/test | Invalid results | Strong near-dup review (dHash16 + hist + SSIM) before splitting |
| R5 | 13 full-frame images rejected by leaf detector | Data loss / demo failure | Full-frame fallback at ≥65% leaf-green ratio |
| R6 | 9 tiny images rejected by size gate | Data loss | Reject <64 px, warn <224 px |
| R7 | Feature schema drift between train/serve | Silent wrong predictions | Schema JSON + version check at startup + unit test |
| R8 | Render cold start / temp FS loss | Confusing UX | Health polling + "Starting analysis service…"; docs state non-persistence |
| R9 | Windows/OpenCV wheel issues | Setup friction | Pin versions, document venv steps, provide `requirements-dev.txt` |
| R10 | Scope creep (MobileNetV2, healthy class, auth, mobile) | Missed deadline | Locked in `docs/DECISIONS.md`; defer to "Future work" |
| R11 | Over-tuned HSV ranges that only work on this dataset | Misleading demo | Document limitation in model card; expose config; test on 5–10 real photos |
